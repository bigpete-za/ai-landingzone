# Weekly Status Report

## Use when

A project or team lead needs a repeatable stakeholder update.

## Required inputs

- Reporting period and audience.
- Approved notes, milestone data, risks and metrics.
- Status definitions (for example Green/Amber/Red) and thresholds, if used.

## Procedure

1. Confirm reporting period and sources.
2. Extract completed work, planned work, changes, blockers, dependencies and decisions needed.
3. Compare metrics only with supplied targets and prior periods.
4. Separate confirmed facts from forecasts or explanations.
5. Highlight overdue, unowned or at-risk items.
6. Draft a concise report using the agreed status definitions.
7. List missing inputs and contradictions for the owner.

## Output

- Overall status and reason
- Progress this period
- Next period priorities
- Milestones / schedule
- Risks, issues and dependencies
- Decisions or support required
- Metrics with period, unit, target and source

## Failure behaviour

Use `Not supplied` for missing metrics, owners or dates. Do not invent status thresholds or explain causation without evidence.

## Human approval

The accountable project owner verifies status, figures, commitments and escalations before sending.
