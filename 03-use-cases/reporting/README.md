# Reporting

## Weekly status report

> Turn the supplied project notes into a weekly status report for `[audience]` covering `[period]`. Use sections: overall status, progress this period, next period, milestones, risks/issues, decisions needed and support required. Use only supplied facts. Mark missing metrics or dates as `Not provided`. Keep it concise and action-oriented.

## Explain performance metrics

> Analyse the attached `[report/workbook]` for `[period]`. First confirm the data fields, units, date range and any gaps. Summarise the meaningful movements against `[baseline/target]`, explain what the data supports, and list possible explanations as hypotheses rather than facts. Show calculations and identify data that should be checked. Do not manufacture a target or causal explanation.

## Executive summary

> Rewrite this report for a senior leader who has `[time available]`. Lead with the decision or issue, then give the essential evidence, impact, risks and recommended next step. Keep the detail needed to understand trade-offs. Preserve caveats and do not change the underlying conclusions.

## Turn a report into actions

> Extract actions from this report. Group by priority and workstream. For each action include source section, proposed action, expected outcome, owner if stated, deadline if stated and dependency. Mark inferred suggestions clearly as proposals.

**Human check:** reporting period, KPI definitions, denominators, calculations, trends, missing data, causal claims and approvals.
